# Модуль "Website Custom Modal"

Модуль `website_custom_modal` добавляет в Website Builder сниппет с настраиваемой
модалкой и отдельным триггером (кнопка или ссылка), который можно перетаскивать
в любую inline-зону редактирования на странице — он не привязан жёстко к
обёртке модалки.

## Функциональность

- Сниппет "Button + Popup (Custom Modal)" в панели Website Builder.
- Открытие по hash-ссылке (`<a href="#modalId">`): срабатывает на ту же страницу,
  где размещён сниппет.
- Триггер выносится из обёртки `.s_custom_modal` и работает на любом
  редактируемом участке страницы. Связь с модалкой держится через `href`.
- Две независимые панели свойств в редакторе:
  - **Custom Modal** (клик по обёртке/модалке) — опции окна:
    - Position: `Top` / `Middle` / `Bottom`;
    - Backdrop: вкл/выкл, цвет;
    - Modal Width / Modal Height: пресеты (`Content`, `Small`, `Medium`,
      `Large`, `Extra Large`, `Full`, `Auto`, `Compact`, `Tall`) и режим
      `Custom` со своими значениями (px/%/rem/vh).
    - Close Button Color.
  - **Trigger** (клик по триггеру) — оформление триггера:
    - Trigger Mode: `Button` / `Link`;
    - для кнопки: variant / size / shape / width;
    - для ссылки: color / underline / weight / size;
    - Trigger Align (`Left` / `Center` / `Right`) — отображается, только
      когда триггер находится внутри обёртки `.s_custom_modal`.
- Корректная обработка iframe-видео при открытии/закрытии модалки.
- Editor preview модалки через "глаз" в панели "Невидимые блоки".
- При дублировании сниппета модалка получает уникальный id, и href
  переписывается только у триггеров **внутри** клонированной обёртки;
  внешние триггеры, указывающие на исходную модалку, остаются нетронутыми
  (поддержка нескольких триггеров на одну модалку).

## Системные требования

- Odoo 17

## Модульные зависимости

- `website`
- `web_editor`

## Python-зависимости

Дополнительные Python-библиотеки для данного модуля не требуются.  
Файл `requirements.txt` не используется.

## Установка

1. Скопировать модуль `website_custom_modal` в директорию `addons`.
2. Перезапустить сервис Odoo.
3. Включить debug режим:
   - `http://<host>:8069/web?debug=true`
4. Перейти в "Приложения", обновить список приложений.
5. Установить модуль `website_custom_modal`.
6. При обновлениях кода выполнить обновление модуля:
   - `-u website_custom_modal`

## Использование

### Добавление сниппета

- В Website Builder открыть панель сниппетов и перетащить блок `custom modal`
  в `.oe_structure` или `[data-oe-type=html]` зону.
- Сниппет создаёт обёртку `.s_custom_modal o_snippet_invisible` с триггером
  (`<a class="s_button_popup_trigger">`) и модальным окном с редактируемым
  контентом.
- Технический идентификатор сниппета: `s_custom_modal`.
- Внутренние служебные классы используют префикс `wcm_`.

### Перенос триггера

- Триггер помечен `o_snippet_drop_in_only` и его можно вытащить из обёртки
  через ручку перемещения в редакторе и положить в любую inline-зону
  (текстовый блок, колонка, баннер и т.п.).
- Связь с модалкой не теряется: триггер остаётся `<a href="#modalId">`,
  а модалка слушает `hashchange` на своём id.
- Когда триггер вне обёртки, опция Trigger Align в его панели свойств
  скрывается — выравнивание берётся из родительского блока.

### Несколько триггеров на одну модалку

- Скопируй размещённый триггер и вставь в любое другое место страницы.
  Все копии указывают на тот же `#modalId` и открывают одну модалку.

### Открытие модалки через прямую ссылку

- На любой странице сайта можно поставить ссылку вида `/page#modalId`,
  где `page` — страница со сниппетом, а `modalId` — id размещённой
  модалки. При переходе модалка откроется автоматически.
- Сниппет работает только на той странице, где он размещён.

## Технические детали

- Состояние оформления триггера хранится в `data-trigger-*` атрибутах
  на самом `<a>` (источник истины), а не на обёртке.
- Опция модалки `data-target=".modal"` — `this.$target` в
  `SnippetCustomModal` указывает на `.modal`, а не на обёртку.
- Класс `SnippetCustomModalTrigger` в редакторе ищет связанную обёртку
  через `closest(".s_custom_modal")`, а если триггер вынесен — по
  `href` через `getElementById`.
- Все правила `wcm_trigger_align_*` вынесены на верхний уровень в SCSS,
  чтобы класс работал и на корне, и на любом элементе.
